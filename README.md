# Norte Trip Planner

A city-exploration app for iOS (and Android) built with **Expo / React Native**. Tell it where you're going and when, and it builds a trip around **everything that matters in that city** — a day-by-day itinerary, a comprehensive Places list, where to eat, and how to get around — from **real, live data**. No mock data, ever.

Check off places as you visit them and watch your **completion rate per city** grow — the goal is "I've seen 100% of Paris", persisted across every trip you plan there.

## What it does

- **Per-city completion**: every must-see place for a city counts toward a completion bar that persists across trips ("You've seen 75% of Paris").
- **A comprehensive Places tab** — the definitive checkable list of a city's landmarks (never cut down to fit a single itinerary).
- **A personalized itinerary**: from a few profile questions (interests, pace, budget style), the app shapes each day's plan — what you love gets prioritized, your pace sets how many sights per day, your budget sets where you eat.
- **Real places & restaurants** from OpenStreetMap, with coordinates you can open in Maps.
- **Getting around** — real transport options from OpenStreetMap (metro, train, bus, tram).
- **A Journal** — everything you checked off, collected as memories with streaks and milestone celebrations.
- **Offline-first**: every trip and your completion progress is persisted to the device via AsyncStorage.

## Data strategy — real data only

The app never invents places or prices. Everything shown is sourced from one of these tiers, in priority order:

| Tier | Source | When it's used |
|------|--------|----------------|
| **1. Live data** | A local proxy (`server/index.mjs`) aggregating free APIs — OpenStreetMap (Nominatim + Overpass), Open-Meteo | Always preferred |
| **2. AI itinerary** | The trip structure (itinerary, descriptions) is generated by an LLM, **seeded with the real places/restaurants fetched above** so it uses real names and coordinates instead of inventing them | Preferred when the AI proxy is running |

> **No mock data.** If a tier fails, the app degrades gracefully (empty lists with a clear message) rather than showing fabricated results.

## Architecture

```
app/                  # Expo Router: index → new-trip → preferences → (trip) tabs
├── index.tsx         # My Trips list (with per-city completion chips)
├── new-trip.tsx      # Trip creation (exact dates or flexible month)
├── preferences.tsx   # Profile: interests, pace, budget style
└── (trip)/           # Guide, Itinerary, Food, Places, Journal tabs
components/           # Reusable themed UI primitives
contexts/             # Trip, Preferences, CityProgress, Progress providers (AsyncStorage-backed)
data/                 # Unsplash hero images, flexible-month options
hooks/                # Theme / color-scheme hooks
lib/                  # Date & formatting helpers
server/               # Local travel-data proxy (Node, free APIs)
services/             # ai.ts (LLM trips), travel.ts (live data)
types/                # Strict TypeScript types
```

## Getting started

```bash
# 1. Install dependencies
npm install

# 2. Start the local travel-data proxy (REQUIRED for live data)
npm run proxy        # → http://0.0.0.0:8787

# 3. Start the app (iOS simulator is the primary target)
npm run ios
```

### Running the full stack

1. **Terminal 1**: `npm run proxy` — local travel-data proxy on `http://0.0.0.0:8787`.
2. **Terminal 2**: `npm run ios` — starts Expo and opens the iOS Simulator.

### Environment variables

Copy `.env.example` to `.env`. Key variables:

| Variable | Purpose |
|----------|---------|
| `EXPO_PUBLIC_PROXY_URL` | Travel-data proxy URL (`http://localhost:8787` for simulator, your LAN IP for a device) |
| `EXPO_PUBLIC_OMNIROUTE_BASE_URL` | AI proxy base URL (port 20128) |
| `EXPO_PUBLIC_OMNIROUTE_MODEL` | AI model, e.g. `auto/best-free` |
| `EXPO_PUBLIC_GROQ_API_KEY` / `MODEL` | Optional primary AI backend (free key from console.groq.com) |

> **No AI tier is required.** With no keys at all, the app still builds a fully live-data trip. If you want the AI itinerary tier, run OmniRoute locally (port 20128) or set a free Groq key.

### Testing on a physical device (Expo Go)

1. Keep `npm run proxy` running (it binds to `0.0.0.0`).
2. Find your machine's LAN IP (`ipconfig` on Windows, `ifconfig` on macOS).
3. In `.env`, set `EXPO_PUBLIC_PROXY_URL=http://YOUR_LAN_IP:8787` and, if using AI, `EXPO_PUBLIC_OMNIROUTE_BASE_URL=http://YOUR_LAN_IP:20128`.
4. Run `npm run ios` and scan the QR with Expo Go (phone on the same Wi-Fi).

## Proxy API

`server/index.mjs` runs on port 8787 and exposes:

```
GET /api/geocode?q=Porto
GET /api/reverse-geocode?lat=41.15&lng=-8.61
GET /api/places?lat=41.15&lng=-8.61&radius=3000
GET /api/restaurants?lat=41.15&lng=-8.61&radius=2000
GET /api/transport?lat=41.15&lng=-8.61&radius=5000
GET /api/weather?lat=41.15&lng=-8.61&startDate=2026-09-01&endDate=2026-09-05
GET /health
```

## Stack

- **Expo SDK 57** / React Native 0.86 / Expo Router (file-based tabs + stack)
- **TypeScript** (strict), **Ionicons**, dark mode via a theme hook
- **Free APIs only**: OpenStreetMap (Nominatim/Overpass), Open-Meteo, Unsplash
- **AI**: local OmniRoute proxy (`auto/best-free`), optionally Groq
